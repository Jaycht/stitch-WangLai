## 踩坑记录（避免重复浪费）
1. **`Record` 命名冲突** —— 自定义业务类型名`Record` 与 TS 内置 `Record<K,V>` 撞车，报 "Type 'Record' is not generic"。**改名 GiftRecord**。教训：业务类型别用内置类型名（Record/Map/Set/Promise）。
2. **项目缺 `@types/react`** —— 装依赖时漏了，导致 JSX 的 `key` prop 报 "Property 'key' does not exist"。表现为组件 props 类型不兼容，根因却是缺类型包。`npm i -D @types/react@^19 @types/react-dom@^19` 解决。
3. **relationship.js 调用签名有坑**（实测得出）：名词短语直接传字符串返回**空数组**，必须传**对象** `r({text:'外婆的哥哥'})`；问句格式才能直接传字符串 `r('外婆的哥哥是谁')`。对方 APK 里的 `relationship.html` 用的是对象形态。封装层两种都试。
4. **react-router 6 的 `<Route>` 不接受 key 属性** —— 动态 `.map()` 生成 Route 会报类型错误。解法：写死四条 `<Route>`，或对懒加载用 `import().then(m=>({default:m.X}))`。
5. **`add_init_script` 在本环境不生效** —— playwright 的 init_script 注入的localStorage 会被 React 首次挂载的 saveDB 覆盖（时序问题，非产品 bug）。**正确做法**：goto 后用 `pg.evaluate` 手动写入，再 reload。
6. **UMD 库在 Node 里 require 会返回 object 而非 function** —— 因为 `module.exports = f()` 被后续IIFE 覆盖。测这类库要在**浏览器**里跑（`pg.evaluate`），Node 测不准。
7. **node 运行时代码路径**：`C:/Users/Administrator/.workbuddy/binaries/node/versions/22.22.2-3/` 不存在，实际是 `22.22.2-6`。
8. **lunar-javascript 无 TS 类型定义**，且方法挂在闭包私有类上（`Object.getPrototypeOf` 也拿不到，ESM/UMD 转译把原型弄丢了）。**正确做法：直接 grep `lunar.js` 源码 + Node 实测每个方法**。几个不存在的：`getNaYin()`（是 `getDayNaYin()`）、`getYearYi/getYearJi`（库没这俩）、`getDayPositionTaiDesc()`（没这个）。
9. 金额输入框的 ¥ 符号和数字重叠 → `pl-6` 改`pl-7 pr-2`。

## 二、设计令牌体系（解决「元素不统一」的根因）
涛哥说「做 UI 时要注意按钮、输入框、下拉等元素大小、字体、排版、样式的统一性」——
**我扫了一遍，发现自己写出了 12 种不同字号**（9px 到 40px），这正是问题所在。

### 令牌分三层
```
1. 令牌层（:root / [data-theme]）—— 所有尺寸字色的唯一来源
2. 组件层（.btn/.field/.card…）   —— 只引用令牌，不写死数值
3. 主题层（[data-theme=A|B|C]）  —— 只覆盖令牌值，不动组件
```
换主题 = 换令牌，组件永远一致，不会走形。

### 令牌清单
- 圆角：`--r-card/--r-ctl/--r-tag/--r-pill`
- 控件高度：`--h-btn/--h-ctl/--h-sm/--h-row/--h-tab/--h-top`（36/36/28/44/54/48）
- 间距：`--s-1` 到 `--s-6`（4 的倍数：4/8/12/16/20/24）
- **字号 7 档**：`--f-xs/sm/md/lg/xl/num/title`（10.5/11.5/13/14/15/18/16）

## 二、关怀模式（大字模式）
### 依据：Material Design 3 官方规范（查了 m3.material.io）
- 最小支持 **200%** 缩放
- 提供 **1x / 1.3x / 1.5x / 2x** 档位
- **只放大字号和行高，padding/间距保持 1x**
- 布局必须能换行、能重排、**不能截断**
- 行高比：小字 1.5 → 大字 1.2

### 实现
6 档：`off 1.0× / xs 1.12× / sm 1.28× / md 1.45× / lg 1.65× / xxl 2.10×`
（比 M3 要求还超一档，超过 200%）

**字号令牌乘 `--fs`**，一处生效全局：
```css
[data-fontsize] {
  --f-xs: calc(10.5px * var(--fs));
  ... 7 个字号全乘
  --lh: calc(1.55 - (var(--fs) - 1) * 0.22);  /* 字越大行高比越小 */
}
```

**容器高度用 max() 保底自动生长**（M3要求「容器必须跟随内容」）：
```css
--h-btn: max(36px, calc(36px - 24px + var(--f-md) * 2.77));
```
这样输入框、行高、Tab、顶栏在大字下自动长高，**不会把字裁掉**。

**间距适度放大**：`--pad-scale: calc(1 + (var(--fs) - 1) * 0.34)`
上限约 1.37 倍 —— 再大一行放不下几个字就得左右横滚，违反 M3「只竖滚」要求。

**不截断**：
```css
[data-fontsize] .truncate { overflow: visible !important; white-space: normal !important; }
```
网格自适应：care-grid-2/3/4/6 大字下改单列。

**关怀模式强制扁平主题** —— 毛玻璃+大字=老手机必卡，且透明底降低可读性，不符合无障碍要求。

| 特大 1.45× | 18.85px | 60.66px | 无 |

## 三、关键踩坑（又是测试脚本）
**追了半小时的"产品 bug"，最后发现是我的测试脚本错了。**

现象：注入 `fontSize:"xxl"/careMode:true`，reload 后变`off/false`，
而 `migrate()` 单测完全正确、`loadDB()+saveDB()` 链路也正确。

**真因**：测试脚本里用 Python `%s` 拼接 JSON 注入 JS 时，
`"try{localStorage.setItem('wanglai.db.v1', %s)}catch(e){}" % s`
—— 第二个 `%s` 传的是**已序列化两次的字符串**，`json.dumps(s)` 把它变成了带引号的字符串字面量，
于是 `setItem(key, "整个JSON字符串")` 写进去的是**字符串的字符串**。
拦截 `Storage.prototype.setItem` 一看，第一次写入值是 `[object Object]`（其实是对象被当字符串传了）。

**教训**（第三次同类问题了）：
1. playwright 注入数据**绝不用 Python `%` 拼接** —— 用 `json.dumps(s)` 生成 JS 字面量，或
2. **把种子数据单独放一个 .py/.json 文件**，用 `from _seed import with_settings` 传 Python 对象，
   只在拼接 init_script 时做一次 `json.dumps()`。
3. 排查「数据被莫名改写」时，**第一步就拦截 `Storage.prototype.setItem` 看写入时序**，
   不要先怀疑业务代码。我这次先怀疑了 5 个地方，全错。

建了 `_ui_compare/_seed.py` 统一管种子数据，后续测试都从它 import。

## 二、系统字体兼容（真问题，不是需求想象）
### 根因：`-webkit-text-size-adjust: 100%` 会阻断系统设置
这条声明的作用是「锁定文本缩放」，会把 Android WebView 的 **textZoom**
和 iOS 动态字号**一起挡掉** —— 用户改了系统字体设置，应用毫无反应。
改为 `text-size-adjust: auto`，倍率统一由自己的令牌控制。

### 系统倍率没有 API 可读 → 只能「量」
`detectSystemFontScale()`：渲染 `font-size:100px` 的「国」字，
量 `getBoundingClientRect().height ÷ 100`。
用 100px 而非 16px，把 subpixel 舍入误差压到 1% 以下。
CJK 字形高度与 font-size 严格线性，比拉丁字母好测。

### 决策：系统已放大时取**较大者**，不相乘
系统 1.3 × 应用 2.1 = 2.73 倍，远超 M3 规范的 200% 上限。
最终 `finalScale = min(2.2, max(appScale, sysScale))`。

### 设置页展示系统状态
「系统字体 [已放大 1.30×] 取系统与应用档位较大者，不叠加」+ 「跟随系统」选项。
用户看得见自己手机的设置到底生效没有。

## 三、⚠️ 本轮踩的坑：倍率被平方

**现象**：应用档位选 1.45，body 字号变成 **27.3px**（= 1.45²）。
**根因**：JS 算了 `max(app, sys)` 注入 `--fs-sys`，
CSS 里又写了 `--fs: calc(var(--fs-app) * var(--fs-sys))` —— **乘了第二遍**。
**修法**：JS 算完最终值后把另一路置 1，CSS 只留 `--fs-sys: 1` 兜底。
教训已写入 lessons-learned.md §7.1。

## 四、⚠️ 全局替换 CSS 前缀的陷阱

把 `[data-fontsize] .truncate` 批量换成 `:root .truncate`后：
1. **注释里的说明文字也被改了**
2. `:root .truncate { white-space: normal }` **无条件生效**
   → 正常档位的列表全变两行，信息密度全丢

**修法**：布局自适应规则改挂在 `data-fontsize-scaled` 上，
由JS 判断 `finalScale > 1.02` 时打这个标记。
**关键**：不能挂在「字号档位」上 —— 档位为 off 时系统仍可能放大，
挂档位会漏掉。字号令牌本身（`--f-lg` 等）则**必须无条件乘 --fs**，
否则标准档时系统字号完全失效。

已验证：1x 密度不变 / 系统 1.3x 时 13px→16.9px、无横向溢出、
搜索框图标文字分离、记录不截断。

## 五、输入历史的下拉不能用遮罩

## 补充（同日）：高亮误导修正

涛哥质疑「↓↑ 选择、回车确认、Esc 关闭是安卓 App 需要的吗」，我一度想删。

## 一、`src/lib/useLongPress.ts`（新建）
长按时长 **480ms**（Android 桌面端体感合适）。三个关键处理：

### 1. 移动容差 10px
手指按下后会本能微动 2~3px，严格按 0 位移判定会导致长按失败。

### 2. 滚动取消
列表滑动时手指持续移动，必须判定为滚动。任一维度超容差即取消。

### 3. 计时器清理
`window.blur` + `visibilitychange` 时必须清掉，
否则页面切走时会在后台误触发。

### ⚠️ 踩坑：短按被判成误触
最初设 `dt < 120ms` 丢弃，实测**60ms 的正常快速点击也不响应**。
根因：自动化测试与部分设备的 pointerdown/pointerup 间隔会被算得更短。
**改成 `CLICK_MIN_MS = 50`**，并加 `performance.now()`（`Date.now()` 毫秒精度不够）。

### ⚠️ 踩坑：多选模式下连续点选无效
多选模式要连续勾选，但 120ms 门槛把 `click()` 的瞬时点击全丢了。
加 `fastClick` 参数 —— **多选模式下跳过这道门槛**。

查material.io/design/interaction/selection + Android 官方 selection pattern，
两条**打脸我 v2.5.0 的做法**：

> "On touch devices, items should **not always display** their checkboxes...

> → 移动端勾选框**不默认显示**（这条涛哥选的正是它）

>  Don't use it to display traditional contextual menus."
> → **长按专门用于选择，不该弹菜单**（我v2.5.0 给菜单塞了编辑/多选/删除三个动作，

> → 滑动批量选择也是规范内的手势（我没做）

## 二、我反对左滑的三条理由（涛哥问了，要给结论）
1. **左滑是 iOS 模式，长按是 Android 模式**。本项目是安卓 APK，
   M3 明确长按=选择。左滑在安卓用户认知里不是「展开操作」。

   左滑露出的操作区会把这些挤掉。微信/钉钉的左滑只在纯文本行用。
3. **左滑与纵向滚动打架**。用户上滑看历史时容易误触左滑，
   动作冲突比长按严重得多（长按有 480ms 延迟 + 10px 容差，能区分）。

**短按不用改**：详情页本来就有「编辑档案」和「删」，
用户想编辑就进去看，正好能确认内容再改，比左滑直接弹删除更安全。

### ⚠️⚠️ 踩了两个真bug，都值得记
**Bug 1：内部 `<button>` 吃掉长按事件**
`TodoRow` 的结构是「外层 div 挂长按 + 里面一个占满整行的 `<button>` 点编辑」。
pointer 事件被 button 消费，冒泡不到外层 → **长按永远不触发，只弹出编辑面板**。
记录页/人员页没这个嵌套结构，所以之前没暴露。
**修法**：多选态时给内部 button 加 `onMouseDown={(e)=>e.preventDefault()}`，
不阻止冒泡但阻止默认聚焦。

**Bug 2：内外两层都响应 click**
修完 Bug 1 后点第二条 → 内外两层都调 `toggleSel` → 选中态闪两次，
并弹出编辑面板。
**修法**：多选态时内部 button 的 `onClick` 传 `undefined`，
点击统一由外层 row 的 `useLongPress` 处理：
```tsx
<button onClick={selecting ? undefined : onEdit}
        onMouseDown={selecting ? e => e.preventDefault() : undefined}>
```

## 五、⚠️⚠️ Git 仓库差点出事（重要）
推送前查状态发现：**`git branch` 显示 `(no branch, rebasing main)`**
—— 仓库卡在一次交互式 rebase 的中间态（msgnum 1/end 1，todo 已空但状态没清理）。

**如果直接提交，改动会被 rebase 吞掉。**
处理：`git rebase --quit` 放弃 rebase → `git symbolic-ref HEAD refs/heads/main`

## 六、⚠️⚠️ 签名方案：本机无 JDK，用纯 Python 生成 keystore

```python
pkcs12.serialize_key_and_certificates(name, key, cert, cas,
    encryption_algorithm=BestAvailableEncryption(pwd))
```
RSA 2048 + SHA256 + 25 年有效期。
**注意 `basicConstraints(ca=False)`** —— 叶子证书必须标false。

`build.gradle` 的 signingConfig 做了**降级保护**：
`keystore.properties` 不存在时退回 debug 签名，保证任何人 clone 下来都能构建。

**根因**：本地 `ls -la` 显示是 `-rwxr-xr-x`（755），

**为什么会这样**：Windows 没有 Unix 权限位，git for Windows 默认

**双管齐下修**：
```bash
# 1. 改 git index 里的权限位（提交后长期有效）
git update-index --chmod=+x android/gradlew
# 确认
git ls-files -s android/gradlew     # 应显示 100755

# 2. workflow 里补 chmod（万一 core.fileMode 被重置也不挂）
- name: Ensure gradlew is executable
  run: chmod +x android/gradlew
```
提交时 git 输出 `mode change 100644 => 100755 android/gradlew` 才算生效。

```yaml
- name: Cache Gradle           # 缓存 ~/.gradle，后续构建省 3~5 分钟
```

**设计依据**：Android 官方「回调以栈的形式添加，最后添加且已启用的处理下一次返回」，
以及原生 Dialog 的 back 优先于 Activity —— 弹层必须比路由优先。

### 退出确认的返回值协议（不需要额外 Java↔JS 通道）
```ts
'ask-exit'   第一次按（根页，未确认）→ 原生不动，JS 弹提示
'exit-now'   2 秒内第二次       → 原生 finish()
'handled'    栈内有处理器 / 二级页返回 → 原生不动
```
MainActivity 只判断 `value.contains("exit")` 即可，**两端都不用额外通道**。

### ⚠️⚠️ 实现坑：不能用全局标记判断「该不该退出」
第一版用 `exitPending` 全局标记，结果**二级页返回也返回 `ask-exit`** ——
因为 `nav(-1)` 后标记也是 false，被误判成「第一次按返回」。
**7 个二级页测试全 FAIL 就是这个原因。**

**正确做法**：`setExitHook` 的函数**返回 boolean**：
- `true` = 本次返回已被应用消化（二级页返回）
- `false` = 要退出但要先问用户

## 三、`MainActivity.java` 重写
```java
getOnBackPressedDispatcher().addCallback(this, new OnBackPressedCallback(true) {
    @Override public void handleOnBackPressed() { dispatchToWeb(); }
});
```
- **不写任何 if/else 业务判断**（官方最佳实践：不要在返回事件

# 2026-10-07 傍晚  CI 第四次排障：Capacitor 插件的 API 用错

## 报错
```
SafFilePlugin.java:66: error: cannot find symbol
  createLauncher = registerForActivityResult(
  symbol: method registerForActivityResult(StartActivityForResult, ActivityResultCallback<ActivityResult>)
  location: class SafFilePlugin
```

## 根因
**`registerForActivityResult` 是 `ComponentActivity` / `Fragment` 的方法，
Capacitor 的 `Plugin` 类没有这个方法** —— 它只是普通 Java 类，不是 Activity。
我在写插件时照搬了 Activity/Fragment 的写法，没查 Capacitor 的 API。

读 `node_modules/@capacitor/android/.../Plugin.java` 确认了：
```java
// Plugin.java 第 115 行，内部是这么注册的：
ActivityResultLauncher<Intent> launcher = bridge.registerForActivityResult(...);
// ^^^^^^^注意是 bridge. 前缀，Plugin 自己没有这个方法
```

## 正确写法（Capacitor 官方机制）
```java
// 启动
startActivityForResult(call, intent, "handleSaveResult");

// 回调：必须是 (PluginCall, ActivityResult) 签名
@ActivityCallback
private void handleSaveResult(PluginCall call, ActivityResult result) { }
```
`startActivityForResult`（Plugin.java:173）内部会`bridge.saveCall(call)`，
**PluginCall 自动带回回调，不需要自己用字段存**。
触发机制在 `Plugin.load()`：扫描 `@ActivityCallback` 注解建launcher 表，
回调时 `method.invoke(this, savedCall, result)`（Plugin.java:155）。

**副作用是代码从286 行缩到 219 行** —— 不需要 launcher 字段、
不需要覆盖 `load()`、不需要 `pendingCall` / `pendingContent`。

## ⚠️⚠️ 建了 `_ui_compare/native_check.py`（本机无 JDK 的应对）
本机没 JDK，Java 只能静态检查，**编译错误要等 CI 才发现**。
这个脚本**直接读 node_modules 里的 Capacitor 源码**核对 API，18 项检查：
```
1. Plugin 基类确实没有 registerForActivityResult（证明用它是错的）
2. startActivityForResult 签名与可见性
3. @ActivityCallback 注解存在
4. ActivityResult 包名与 Capacitor 一致
5. callbackName 字符串与 @ActivityCallback 方法名一一对应
6. 代码里没有用 ActivityResultLauncher / Contracts / onActivityResult
7. 没有多余的 pendingCall / pendingContent 字段
8. 括号配平（逐字符扫描，正确处理注释与字符串）
```
**这能把「等 CI 报错」变成「推之前就报错」**，和 ci_check.py 同一个思路。

### 脚本自身踩的坑
`grep startActivityForResult` 把**注释里的错误示例**也扫进去了，
报「callbackName "callbackName" 没有对应方法」。
**修法：先剥注释再扫**（`re.sub(r'/\*.*?\*/', '', s, flags=re.S)`）。

## 一、⚠️⚠️⚠️ 备份失败：插件注册**时机**错了
```java
// 我写的（编译通过、装上运行就报plugin is not implemented）
@Override
public void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    registerPlugin(SafFilePlugin.class);   // ← 无效
}
```
读 `BridgeActivity.java` 才看清时序：
```java
protected void onCreate(Bundle) {
    super.onCreate(...);
    ...
    this.load();                          // ← Bridge 在这里就建好了
}
public void registerPlugin(Class<? extends Plugin> p) {
    bridgeBuilder.addPlugin(p);           // ← 只改 Builder，来不及了
}
protected void load() {
    bridge = bridgeBuilder.addPlugins(initialPlugins).create();
}
```
**`registerPlugin` 只往 builder 塞类，而 `super.onCreate()` 里已经 `load()` 完并建出 Bridge —— 之后再改 Builder 完全无效。**

**正确做法**：覆盖 `load()`，在 `super.load()` 之前塞 `initialPlugins`：
```java
@Override
protected void load() {
    initialPlugins.add(SafFilePlugin.class);   // 必须在这之前
    super.load();                              // 这里才 create()
}
```

```css
  box-shadow: inset 0 1px 0 rgba(255,255,255,.9), 0 -2px 12px rgba(0,0,0,.06);

[data-perf="low"] .tabbar {         /* 没有 blur 就必须靠底色挡住 */
  backdrop-filter: none !important;
  background: rgba(252,253,252,0.985);
}
```
